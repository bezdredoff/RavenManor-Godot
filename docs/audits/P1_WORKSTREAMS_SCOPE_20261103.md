# Raven Manor — аудит P1, группировка работ и границы текущей версии

**Дата:** 2026-11-03, после смерженного PR #151. **Цель:** уменьшить дублирование работ в активном бэклоге и сохранить реальное состояние каждого deliverable. Этот аудит **не** генерирует ассеты, не меняет gameplay, runtime, сюжет или сохранения.

## Контрольная выборка из 238 задач

Сразу после #151 источники CODE/GAP/GFX вместе содержали **13 открытых P0**, **91 открытый P1** и **18 открытых P2** (всего 122 открытых задачи; остальные имеют terminal статусы). После переоценки **26 незакрытых P1** переведены в **P2** без изменения `status`, `qaState`, `approvalState` или реального объёма реализации. Итого:

| Категория | Было | Текущая очередь |
|---|---:|---:|
| P0 | 13 | **13** |
| P1 | 91 | **65** |
| P2 | 18 | **44** |
| Всего открытых задач | 122 | **122** |

**Это не сокращение требований с 122 до 10.** Ровно **78 открытых P0/P1 задач** теперь имеют единый `workstreamId` в `active_workstreams.json` и 10 приёмочных потоков. Первичные IDs и отдельные критерии не удалены, объединены только планирование/артефакты QA. Неисследованная фича не может получить `accepted` из-за попадания в поток.

## 26 задач, для которых P2 честнее текущего P1

Все ниже **остаются открытыми** в своих `proposed`/`ready` состояниях:

| Категория | IDs | Причина переноса |
|---|---|---|
| Расширение игрового функционала | `CODE-04-02`, `CODE-06-02`, `CODE-07-03`, `CODE-08-01` | Shared audio bridge, расширенные расписания NPC, revisit clues, season-wide progression после совместного Hall gate |
| Массовое производство сезонов | `CODE-12-W1/W2/W3`, `RM-GAP-007` | Не начинать главы II–IV production wave только из-за переведённых исходных каталогов |
| Старый общий art automation | `RM-GAP-005`, `GFX-05-03` | Не восстанавливать универсальный art job/keyframe pipeline для уже утверждённых 62 VN-изображений |
| Дополнительный keyframe batch | `GFX-06-01/04/05/07/10`, `GFX-11-T05` | Полная перестановка 280 cues и покадровые изображения требуют сцено-специфичного запроса; существующие editor FX не равны image animation |
| Исследовательские chibi/второстепенные герои | `GFX-07-02/03/07/08` | Tool/proportion comparison включается в один GFX-07-01 spike; Rowan/Lucas map batches — после реального авторского маршрута |
| Все комнаты/второстепенные props | `GFX-08-03/04`, `GFX-09-03/04` | Полный material/landmark atlas и второстепенные prop families не должны задерживать физический Hall и обязательные предметы |
| Полировка эффектов | `GFX-10-06/08` | Дополнительный shine/glow и унификация всей UI палитры после реального игрового touch и основной читаемости |

Ни одна из этих задач **не** архивирована как `superseded`: при появлении конкретной сюжетной сцены/релизного gate приоритет можно повысить отдельно с новой evidence. Например, `GFX-07-02/03` входят критериями выбора минимального пилота `GFX-07-01`, а не второй обязательной генерацией.

## Что принципиально остаётся P1

- **Локализация:** `LOC-EN-QA`, `LOC-BE-QA`, `RM-GAP-013` — один tri-locale test, отдельное подтверждение каждой локали/UX.
- **VN Studio:** `VNS5-07F/07F2`, `VN-EDITOR-07/08`, `VN-CAST-MATRIX`, `VN-BG-DEVICE-QA`: автоматизированная работа ≠ pixel/UI parity и native device QA.
- **Map Hall:** `GFX-08-01/02/08/09/10` и `CODE-05-03` остаются, потому что утверждённый VN-фон не является безопасной физической картой.
- **Match-3:** `CODE-02-01/03/05` и `GFX-10-01…05/07` остаются для реальных свайпов, correct hints, popup и визуально читаемого набора.
- **Chibi:** `GFX-07-04` identity, `CODE-06-01`, `RM-GAP-011` и основные Evelyn/Ada из P0 остаются актуальными.
- **Map props:** `GFX-06-06`, `GFX-09-01/02/05/06`, `CODE-07-01/02` остаются; отложена только самостоятельная библиотека *VN props* `VNS5-08`, не восстановление/интерактивные объекты карты.
- **Device/asset contract:** не предполагать готовность импортных pivots/alpha, safe area или accessibility по SHA одних VN WebP.

## Предохранители

1. `production_progress.json` остаётся источником task statuses и приоритета. `active_workstreams.json` — **только группировка**, не новый статус/approval source.
2. Каждая из 78 актуальных P0/P1 задач принадлежит **ровно одному** потоку. В P2/архиве workstream пустой; можно открыть задачи в фильтре «Все задачи».
3. `build_production_dashboard.py` отвергает несуществующие ID, дубли, неверные фазы и отсутствие группы у любого текущего P0/P1. `validate_active_workstreams.py` и тесты дашборда фиксируют те же инварианты и 26 приоритетных изменений.
4. `validate_backlog_dependencies.py` и `reconcile_gap_statuses.py` остаются обязательными: цикл зависимостей, deferred blocker или рассинхронизация статусов не допускаются.
5. Стабильные IDs CODE/GAP/GFX, исходный архитектурный CODE plan, все открытые issues, реальные URL/PR evidence, арт-ассеты и runtime не трогаются.

**Следующая работа после мержа:** по `WS-VN-STUDIO`, `WS-LOCALES` и `WS-MOBILE-HANDOFF` подготовить небольшие QA acceptance batches. Это отдельные owner/native проверки, не приказ о новой генерации или массовом сезонном производстве.
