# RM-PIPE-004 — Hall visual calibration, foreground and physical-footprint acceptance

Date: 26 October 2026. **Status: partially implemented / approval pending.** This document distinguishes implemented tooling from artwork that we cannot credibly approve yet.

## Objective and immutable contract

Room Builder exports the Hall room; the committed generated Godot PackedScene is consumed by the active **Whole Manor Map**. The next production goal is one coherent accepted Hall where the generated painting's doors/stairs, imported furniture cutouts, sprite pivots, character occlusion and physical obstacles all correspond to the same world geometry. We **must not silently regenerate or approve a background** just because our coordinate checks pass.

Authority remains `data/raven/season1_world_map.json`: Hall world bounds **(500,150,700,690)**, five door markers, two stairs and a single legacy seat collision. The 65° projected floor is **Y × sin(65°)**, and upright sprites use their bottom-centre foot position without squashing their art height. Actor location is never imported from Builder.

## In-game comparison protocol

1. Open [Prototype Lab](https://bezdredoff.github.io/RavenManor-Godot/) → **5 · Whole Manor Map**. The usual **Импорт** view remains the default.
2. Expand **Настр.** and tap **Калибр.: СКР**. Green = existing active portal axis; red crossed marker = future destination; cyan boxes/treads = map stair footprints; orange = current combined seating collision; lime = the three proposed chair/table contact boxes; violet = current actor foot-depth reference.
3. Switch the **Вид** control to **AI1** and back to **Импорт**. Visually compare the *painted* stair bottoms/landing, side door frames, entry threshold and gallery against these fixed world markers. Use 0.68× / 0.74× / 0.80×.
4. With the same tools open, tap **Кресла: ЦЕЛЬНО** to enable **Кресла: 3 ТЕСТ**. Try walking around each chair and table; confirm at least the same door routes remain reachable. This is temporary, resets on re-entering the scene, is never persisted to Raven save and never changes interaction hooks.
5. Switch back to **Кресла: ЦЕЛЬНО** (the original blocking footprint) and hide calibration markers. Use **Габариты: ВИД** to double-check all original bounds separately.
6. On 390×844, 412×915 and 430×932 mobile screens, capture screenshots for both image modes, with and without overlays. Check actor crossing chair/clock foot-depth thresholds, door marker readability, staircase approach and no clipping by UI safe areas.

## Acceptance criteria (not yet all met)

- 5/5 door *image openings* visually line up with the true map portals: closed future markers are not represented as accessible doors.
- 2/2 staircases have verifiable matching perspective, lower tread/landing endpoints and unambiguous player occlusion. No character silhouette draws through a foreground railing.
- A staircase or furniture pilot PNG must not visibly duplicate details already baked in the painting (sconces, gallery portraits, runner, stair rails).
- When the player walks **behind** a chair or clock, its correctly masked alpha covers the player, and when **in front** the player's silhouette is visible. Test actor foot Y below, equal to and above an item's foot Y.
- All three separated furniture contacts must be approved from actual image floor-contact evidence (not just a 32%-height heuristic). Canonical route tests pass with both modes; original one-piece obstacle remains the default until sign-off.
- Every imported PNG state corresponds to real source art (clean/dirty/broken not substituted), with pixel-safe foreground masks and no placeholders in the accepted playable Hall.
- No change to campaign progression, saves, unlocked doors, VN/Match-3 transition points or routing unless explicitly covered by independent migration tests.

## What the automated tests establish

The Godot smoke asserts door/stair source integrity, visual import parity, default combined collision, reversible independent seat preview, no ghost blocker in the old seat cluster when three-piece test is on, and stable actor front/back occlusion threshold. Python tests prove the register regenerates byte-for-byte from current source maps, validates original five doors and original staircase bounds, and never grows an individual contact beyond the old seats rectangle. Existing route and gated-door tests continue running in both navigation modes.

These tests **cannot certify** actual AI-generated image pixels or perception. The last art and gameplay acceptance pass requires user review on actual mobile screens and approved revised source background/prop variants.

## Follow-on implementation once images are accepted

Create clean architectural base artwork with exact painted doorway/stair endpoints (one shared projection guide for every generation). Separate background static architecture from furniture/portraits and foreground rail/wall mattes with alpha. Calibrate per-asset local foot-contact and interaction masks, generate clean/dirty/broken variants, then promote a verified **art-versioned** Hall contract (never silently overwriting the existing draft). Only once path, occlusion and state regressions are green should individual contacts replace the old combined seats logic and expand to other rooms.
