# GFX-08-06 / GFX-08-07 — аудит VN-фонов и решение по текущей версии

Дата: 2026-11-03. Основание: проверки актуального `main` после PR #147 и решение не генерировать фон, пока нет сцены, использующей конкретное состояние.

## Проверенные факты

- Художественно утверждены **26 существующих 1080×1920 WebP** в `data/raven/production/vn_background_catalog.json` (дата утверждения 2026-11-02). Они относятся к **10** семействам: BG-HALL, BG-LIBRARY, BG-APARTMENT, BG-ROAD, BG-ENTRY, BG-BEDROOM, BG-BATH-VIGNETTE, BG-KITCHEN, BG-GARDEN, BG-CONSERVATORY.
- **28/28** канонических VN-сцен имеют ровно обозначенный вариант `(backgroundId, lighting, roomState)`, который разрешается одним каталогом в Godot runtime и VN Studio. **BG-CORRIDOR** в нынешних сценах не используется.
- Все **26 записей** включают исходное PNG-имя, размеры первоначального изображения, дату/тип происхождения, точный game-ready путь и SHA-256 производного WebP. Код `tests/raven/vn_background_gallery_smoke.gd` теперь проверяет на реальных файлах **все 26 SHA-256**, включая ранее пропущенные при проверке Hall/Library, и автоматически проходит по всем 28 scene-shot bindings.
- Из 26 утверждённых вариантов **5** не назначены непосредственно `vn_staging.json`: `BG-APARTMENT:day:inhabited`, `BG-APARTMENT:evening:rainy`, `BG-APARTMENT:night:rainy`, `BG-ENTRY:dusk:approachable`, `BG-ENTRY:day:overgrown`. Это дополнительные *уже принятые* изображения библиотеки; их не удаляем только ради сокращения до 21.
- Записан **результат** генерации и исходный asset-pointer, но **не** восстановлены все исходные ChatGPT-промпты, reference boards, временные параметры, промежуточные image edits и полный регенерируемый граф. По одному имени PNG и хэшу воспроизвести точное оригинальное изображение нельзя.

## GFX-08-06 — происхождение исходных ChatGPT-фонов

Первоначальное требование: для **каждого** фона сохранять исходный бриф, reference board, target resolution, style contract, landmarks и все правки, а принятый master считать источником любых дальнейших производных.

Для существующего production VN достаточно более узкого гарантированного контракта: **неизменяемые утверждённые WebP + источник/дата/первичный размер + SHA + стабильные scene/state IDs**. Это теперь автоматически проверяется. Первоначально заданная *полная prompt-level воспроизводимость* не реализована и не должна объявляться таковой.

Рекомендуемый статус исходного production-процесса — **`superseded`**, а не `accepted`: его повторно реализовывать задним числом для 26 уже утверждённых изображений не требуется. Архивные пробелы честно фиксируются. Для **новых** ChatGPT/ComfyUI ассетов по возможности сохранять исходный запрос, итерации, reference, seeds/модель при их наличии и immutable raw; правило создания нового арта не отменяется.

## GFX-08-07 — отделённые lighting/state overlays

Первоначальное требование: единый base master и отдельно накладываемые light grades/state masks, желательно pixel-registered; ChatGPT лишь для крупных semantic variants.

Фактически существующая версия VN использует **полные предрендеренные кадры** для точного состояния, а не анимацию интерполируемого света/разрушения/восстановления в рамках одного master. Это согласуется с утверждёнными изображениями и сценами. Сами независимые изображения **не** считаются выполненными state-overlays: композиции Hall, Library, Apartment, Bedroom и другие могут слегка различаться. В частности, вечерний вариант Kitchen и dusk Conservatory не имеют гарантии идентичной геометрии; кадр `BG-APARTMENT:day:packed_boxes` не доказывает наличие визуально читаемых коробок.

Рекомендуемый статус старого overlay-only производственного подхода — **`superseded`** для текущих VN-фонов: переключение готовых изображений работает без выделенных слоёв. Если появится необходимость *плавно* анимировать освещение, непрерывную реставрацию, пиксельно стабильный dissolve или процедурную маску, заводить **новую отдельную задачу** на конкретную сцену/семейство и не подменять готовый source молча.

Отдельная геометрия карты, проходы, коллизии, Room Builder, map props, physical restoration states, мобильное визуальное QA и VN runtime QA **не закрываются** этим решением.

## Критерии автоматической приёмки текущей версии

1. У всех 26 production-записей `status=accepted`, точные tuple IDs, `sourceImage`, `sourceSize`, `sourceType`, `approved` и корректный физический путь.
2. Все WebP на диске действительно соответствуют SHA-256 в каталоге, не только ранее добавленные 17.
3. Все 28 исходных scene-shots разрешаются в именно свои утверждённые texture variants, без несуществующих комбинаций.
4. Предыдущие конкретные контракты сюжетных сцен, отсутствие неподтверждённых вариантов и разрешение exact BG-CORRIDOR остаются неизменными.
5. Никакой patch не меняет готовые изображения, staging/campaign/save или физическую геометрию.

**Проверка:** `godot --headless --path . --script res://tests/raven/vn_background_gallery_smoke.gd --quit-after 120`, также выполняется в стандартных Linux/Windows checks.

Прохождение CI доказывает текстуры, размеры, хэши и существующие пути; **не** доказывает художественное совершенство, pixel-perfect совпадение разных состояний, оригинальный ComfyUI/ChatGPT prompt replay или визуальное QA на настоящем телефоне.
