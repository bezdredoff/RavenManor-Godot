# GFX P0 — переоценка по уже полученному арту (2026-11-03)

## Решение и фактическая база

Пользователь предложил пересмотреть почти все старые P0-задачи графики: фактически все необходимые **статичные VN-изображения персонажей** уже получены, тогда как отдельные mildly-chibi персонажи для карты ещё не сделаны.

Проверено по текущему `main` после PR #148:

- `vn_character_catalog.json`: **62** художественно утверждённых полноразмерных изображения четырёх действующих героев (Эвелин 18, Ада 14, Лукас 14, Роуэн 16) с несколькими позами, эмоциями и композитами с предметами в руках. Принятие этих изображений зафиксировано отдельно в `GFX-06-02/03`, но не доказывает полную матрицу всех сочетаний pose×emotion и покадровую анимацию.
- `vn_background_catalog.json`: **26** художественно утверждённых VN-фонов. Каждая из **28** канонических сюжетных сцен имеет точный tuple и loadable texture; архивный GFX-08-06/07 закрыт как `superseded` в PR #148. Это не геометрия хаба или state sprites для карты.
- В `assets/raven` есть каталоги `characters`, `hall`, `vn_backgrounds`, `vn_pilot`, но **нет утверждённой серии chibi/map sprites**. `assets/prototypes/onoe` — технический UPDS-плейсхолдер и не Raven map-персонаж.
- `GFX-10` (8 Match-3 tiles, blockers, specials, skin), `GFX-08-01/02/08/09` (финальный Hall/map architecture), `GFX-09` (отдельные объекты/состояния), `GFX-06-04/05/08` (настоящая анимация и keyframes) сохраняют свои отдельные требования. Их **нельзя** закрыть наличием VN-картинок.
- Реальный portrait/mobile/device QA Hall/VN, отсутствие наложений/crop, reduced motion и игровая сохранность — отдельные незавершённые проверки.

## Почему P0 был раздут

`scripts/raven/tools/build_production_dashboard.py` присваивал `priority="P0"` автоматически **всем задачам целиком** в секциях GFX-00, GFX-01, GFX-02, GFX-03, GFX-04, GFX-05 и GFX-11. Это приоритет первоначального production-плана **до создания арта**, а не критичность для текущего игрового релиза. Задачи без override также получали `proposed` несмотря на реальные результаты.

До аудита: **63** GFX P0, включая **57** незакрытых (`proposed`/ `ready`), 2 ранее `superseded`, без честной привязки к полученному арту.

После предлагаемой сверки: **7 активных GFX P0**. Среди тех исходных 63: **43 `superseded`**, **2 `accepted`** (только художественные компоненты Hall), **1 `integrated`** (двухместная постановка) и **17 `ready`** (конкретные QA/контракты или игровые пробелы, в основном P1). Ни один исходный P0 не остаётся без записанного решения.

`superseded` означает, что старый **метод** стал не нужен после утверждения результата другим путём. Он **не** означает, что исходный эксперимент, измерение или чеклист был выполнен. `accepted` применяется только к конкретным уже принятым изображениям; `integrated` — к проверенной постановке без гарантии device acceptance.

## Что НЕ закрыто этой сверкой

- Новые chibi-изображения **не генерировались и не утверждались** этим PR. Нет фейкового тестового assetId или выдуманного контакта с локальным ComfyUI.
- Не отменены физические props, stateful map items, Hall map construction, locked corridors, код навигации и кликабельные якоря.
- Не закрыты 8 Match-3 тайлов и blockers; совпадение механики/UPDS renderer не доказывает окончательное игровое оформление.
- Не закрыта полная VN performance matrix (в частности, некоторые pose/emotion комбинации), keyframe sprites, device/crop/text overlap или разные локализации в реальном экране.
- Не подтверждены не проводившиеся ранее VNCCS/model/style comparative tests, turnarounds и full deterministic replay; они лишь сняты как **необязательные исторические методы** для уже принятого статичного результата.

## Техническое правило для дашборда

Приоритет в graphics roadmap продолжает обозначать **исторический default секции**. `production_progress.json` теперь может задавать явный `priority` только для **GFX** задач; не-GFX priorities не изменяются. Значения валидируются как `P0/P1/P2`, исходные записи остаются в roadmap. Изменение статуса без фактического evidence и/или без обязательного `supersededBy` по-прежнему запрещено.

Регрессионный тест `test_gfx_p0_scoped_to_active_chibi_and_hall_acceptance` фиксирует список семи P0, различие `art_approved` и ручного QA, и сохранность 26+62 принятых ассетов. Внесение настоящего chibi-арта будет отдельным PR с тестом размеров, alpha, character anchors и runtime.

**Итог:** P0 становится списком ближайших задач для достижения рабочей мобильной карты, а не списком экспериментов, которые когда-то предшествовали генерации уже принятого арта.
