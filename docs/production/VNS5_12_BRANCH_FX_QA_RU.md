# VNS5-12 — три варианта выбора и микро-FX, только в черновике

После merge **VNS5-11** и этого PR открой Godot 4.7.2 → VN Studio → Raven Manor → **Дополнительно…** → **QA · выбор 3 героев + FX**. Подтверди. В конец текущего draft добавятся 4 сцены после уже существующих новых сцен. Исходные 28 сцен и 280 реплик не меняются.

Первая новая сцена `QA · выбор героя (черновик)` включает авторский текст с выбором, затем реплики Эвелин, Ады и Роуэна. Stage автоматически показывает их на BG-HALL (реально существующий утверждённый вариант), в трёхместном шаблоне. На одной и той же первой реплике Story Map есть три **оранжевых** choice-провода: A → Эвелин, B → Ада, C → Роуэн. В каждой из трёх новых сцен отдельная **оранжевая** обратная связь `scene → выбор`. Канонические зелёные провода не меняются, QA-сцены не соединены с игровым runtime.

Во вкладке Animation для общего кадра: **Эвелин — fade_in/enter, Ада — breathe/idle, Роуэн — shake/idle**. В личных сценах соответствующий FX привязан к одному персонажу. Это существующие bounded preview-FX, не новые арт-файлы или анимационный scheduler; `blink` остаётся proxy. Выбор активен только в редакторе; в самой игре его пока нельзя кликать как реальный runtime-переход.

Проверь Story Map в режиме «Все сцены», щёлкни три оранжевые связи, открой каждую новую сцену и убедись в обратном проводе. В Animation проверь Play/Pause и scrub до 0–5 с, отличимые fade/breathe/shake. Сделай Undo один раз — все четыре QA-сцены и их FX исчезнут; Redo вернёт. Только при необходимости нажми **Сохранить Raven-черновик**. Другие изменения локального черновика не перезаписываются. При повторном нажатии кнопка откажет, если QA-демо уже присутствует.

Связанный тест: `tests/raven/vn_studio_branch_demo_smoke.gd` (валидирует 3 choice + 3 возврата, cast images, FX, undo, сохранность исходников). Текущие артовые approvals, история, locale/Match-3 и saves не меняются.

## Дополнительная проверка сериализации

Новый QA smoke обнаружил, что `JSON.parse_string` может прочитать целые миллисекунды FX как `float` (например, `1400.0`), а исходный `StageFx.validate` принимал только Variant типа `int`. Добавлена проверка **математической целочисленности и конечности**: `1400` и `1400.0` допустимы, `1400.5`, NaN, бесконечность и выход за пределы — запрещены. Регрессия покрыта как standalone StageFx smoke, так и полным JSON round-trip 4-сценного демо. Это важно для реального сохранения `user://` черновика.

## Дополнительный автотест после #145 (2026-11-03)

Контент для ручной проверки **уже существует** в `Дополнительно… → QA · выбор 3 героев + FX`; повторного добавления сценария в канон не требуется. Тест `vn_studio_branch_demo_smoke.gd` дополнительно проверяет:

1. Четыре QA-сцены добавляются именно после существующей черновой сцены. Существующие authored lines, stage/портреты и сериализация сохраняются; повторный append блокируется.
2. В реальном `RavenStoryGraphView` видны три оранжевых исходящих провода. Клик по зелёному порту не разрешает редактировать канон; клик по оранжевому выбирает точный edge. Изменение подписи проходит через сигнал Store и имеет Undo/Redo.
3. В настоящем `RavenStageDesigner` три cue доступны в Timeline. Play/Pause/Reset работает, перемещение времени клипа до 1750 мс проходит Store validation/Undo/Redo и JSON roundtrip.
4. Добавление, preview и редактирование не пишут в `user://` без явной команды Save.
5. Отдельный `vn_studio_raven_story_smoke.gd` проверяет невозможность сброса «чужого» черновика при SHA drift, затем восстанавливает его исходные байты и проходит подтверждённое архивирование.

Это автоматические Godot headless проверки сигналов/данных UI; они **не доказывают** качество ручного drag мышью, видимость текста/картинок или работу на реальном Windows/телефоне. VNS5-10 и VNS5-07F1/F5 остаются с корректным кодовым статусом `merged`, а более широкий VNS5-09 — открытым до отдельной приёмки.
