WebP сохранён **без потерь**, с исходными размерами и прозрачностью: 1088×1920 для базовых наборов и Ады/Лукаса/Роуэна; 2048×3614 для дополнительных поз и предметов Эвелин. При переносе проверено точное совпадение декодированного RGBA с PNG, включая прозрачные пиксели. Всего около 38.2 MiB. У каждой записи есть SHA-256 исходного PNG, экспортированного WebP и встроенного workflow, относительное имя источника и дата принятия. Локальные абсолютные пути и полные ComfyUI-графы с изображениями в публичный каталог не перенесены.

Источники: локальные FullBodyEmotions, PerformanceApproved, PropApproved и принятые StoryPoses Эвелин. Исключены базовые неодетые identity studies, старые версии костюмов, квадратные/обрезанные эмоции, контактные листы, манекены, неудачные глаза/шея, старые варианты книги, обрезанные конечности и промежуточные пробы. Сюжетный реквизит входит в изображение вместе с руками; его нельзя дополнительно дублировать отдельным prop overlay.

## Использование

В Godot открыть **VN Studio → Raven → сцена → персонаж**. После полей позы и эмоции есть список принятых изображений выбранного героя. Выбор конкретного кадра устанавливает его позу/эмоцию и сохраняет стабильный `assetId` в существующий staging draft; сохранение/экспорт проходят прежнюю проверку постановки. Персонаж, поза и эмоция должны соответствовать выбранному asset ID. Смена позы или эмоции возвращает автоматический выбор.

В общей **Библиотеке Raven → Персонажи → accepted** доступны все 62 кадра и четыре обзорные карточки героев, фильтры по семейству, поиск и сравнение A/B с реальным изображением и SHA. Предметы, уже нарисованные в руках, не выдаются за отдельные prop-слои.

Позиции и размеры портретов в Studio и игровом композиторе рассчитывает общий `raven_vn_portrait_layout.gd`: ширина рамки 77% для одного-двух персонажей, 60% для трёх; высота 73%. Исправлено сдавливание всех Studio-портретов в центре, нормализованные координаты и обратное преобразование при перетаскивании сохраняются. Нативные исходники не уменьшались: импорт включает mipmaps и линейную фильтрацию для чистого уменьшения рисунка в игровых кадрах и миниатюрах.

Автоматический выбор сначала ищет точное сочетание. Для ещё не созданной эмоции в сюжетной позе может показываться нейтральное изображение **той же позы**, с предупреждением в VN Studio. Отсутствующие сочетания не объявляются созданными. В игре нет технических меток этого fallback. Весь pose × emotion × prop Cartesian product не создавался. Точное назначение предмета доступно через выбор изображения; автоматические line cues подбирают только реквизит того же персонажа и позы. Например, фонарь Ады нельзя получить из cue Эвелин.

Оба действующих игровых VN-экрана используют этот же resolver. Для RM-VS-01 без lineId разрешено только однозначное совпадение оригинального русского текста с canonical catalog; ID по индексу массива не выдумывается. Если совпадения нет, используется исходная постановка сцены. Текст, локализация, progression, scene/line IDs и формат кампании не меняются. VN Studio продолжает писать только staging drafts до явного Apply/экспорта. UPDS donor и его приватные изображения не затронуты. Новый resolver — Raven asset adapter; существующие VN UI, paging, staging и безопасный draft store переиспользованы.

## Проверка и оставшиеся этапы

`tests/raven/vn_character_art_smoke.gd` проверяет загрузку всех 62 ресурсов, размеры, exact/fallback, защиту от неверного персонажа/asset ID, реальный выбор и рендер каждого изображения в VN Studio, round-trip staging draft и оба игровых VN-экрана. Тест включён в Windows и Linux checks.

Для приёмки интеграции остаются CI на опубликованном head, ручной просмотр в Godot Editor и на мобильном устройстве. Этот импорт не добавляет моргание, рты, промежуточные кадры, готовые микроанимации, новые эмоции для сюжетных поз или чиби-графику карты. Карта сохраняет существующие технические заглушки. Утверждение наборов персонажей не утверждает предлагаемые поздние главы как runtime-канон.
