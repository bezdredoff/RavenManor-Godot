# VNS5-07C1 — интерактивная Story Map (draft-only)

Основание: issue #121, merged PR #122 / #123. **Статус: PR review; нативная QA и CI на этой ветке ещё не подтверждены.** Это первый небольшой этап VNS5-07C, не реализация нелинейного gameplay runtime.

## Пользовательский сценарий

- Story Map отображает реальные канонические gate-зависимости и отдельно **черновые** scene/choice/match3 предложения.
- **Один клик по ноде-сцене** выбирает её в основном Director (синхронизация sceneId); панели содержимого и Story Map получают новый текущий source. Клик по gate или Match-3 объясняет, почему канонический узел нельзя изменять.
- **Протяните провод** от правого порта текущей исходной сцены к левому порту целевой сцены: создастся только локальный draft edge. Тип берётся из редактора под графом (`scene` или `choice`); для `choice` сначала надо выбрать checkpoint lineId и A/B/C. Пустая подпись при drag создаётся автоматически. Drag к существующему Match-3 узлу создаёт `match3` draft с каноническим level ID.
- В списке черновых переходов клик по строке **подставляет все параметры** в поля типа, target, checkpoint, choice key и label. Кнопка **Сохранить связь** меняет выбранный edge без смены его стабильного edge ID. **− Связь** удаляет выбранный draft; оригинальный trigger/каноническая линия не удаляется.
- Если source не выбран, target не существует, выбор дублируется или возникли два безусловных перехода, `Graph.validate` блокирует изменение и показывает причину.
- Для канонических gate lines и source из другой сцены drag не меняет draft/источник; необходимо сначала выбрать нужную сцену.

## Что не меняется

- `storyGraphPatches` сохраняется в `user://` локальном SHA-locked draft, новый формат данных не вводится; старые drafts работают.
- `Graph.build` по-прежнему показывает только реальные route gates; не придумывает последовательность сцен.
- **Нет** активации игрового branching runtime, choice effects, автоматической промоции или записи в `res://`, GameSave/Reducer/UPDS.
- Перетаскиванием по канонической линии не удаляем гейт. Для выбора конкретного draft edge при нескольких параллельных ветках A/B/C используйте список, а не неявное редактирование линии.

## Проверки для владельца (Godot 4.7.2, Windows)

1. Открыть Director → Story Map на `RM-BEAT-00-01`. Кликнуть другую сцену: её sceneId должен появиться в основном списке сцен с первого клика, не нужно угадывать кликабельную область.
2. Выбрать исходную сцену, `scene`, протянуть провод на другую сцену; увидеть draft edge. Если в этой сцене уже создан безусловный переход, должна появиться понятная ошибка, без изменения данных.
3. Выбрать `choice`, контрольную реплику и ветки A/B; создать две связи через drag к сценам, проверить разные цели и labels.
4. Кликнуть строку одного draft edge в списке, поменять label/target и нажать «Сохранить связь». Затем удалить только его. Проверить стабильный edgeId и вторую ветку.
5. Сохранить черновик, закрыть и снова открыть Godot; сравнить связи и node selection. Экспорт Story Map Review не должен активировать runtime.
6. Проверить 800×640, 1024×640 и 1366×768 с full/focus, проверить, что канонические gate/Match-3 не изменились; сравнить исходные SHA и игровой прогресс.
