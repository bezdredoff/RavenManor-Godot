## Risks and rollback

- The `Pages build_type` REST field is `workflow` for custom GitHub Actions publication and `legacy` for branch publication. If API access is unavailable or field is unexpected, deploy fails **with an actionable message**; do not assume success. Pages `write` permission in the existing deployment job includes read, no PAT required. See https://docs.github.com/en/rest/pages/pages .
- Changing Source is a repository setting, not a code change; **CI cannot flip it automatically**. The conditional guard intentionally makes a wrong configuration visible quickly rather than silently publishing the wrong branch artifact.
- Increasing the deployment timeout from default 10 minutes to 30 minutes addresses slow `syncing_files` after excluding competing publishers, but does not heal a GitHub Pages backend outage or guarantee performance. This is a bounded temporary resilience policy, not arbitrary retries or hidden failures.
- Job-level `concurrency` coordinates custom workflows that adopt the same group; GitHub's separately generated legacy workflow does not automatically share it. One-time settings switch remains required.
- Rollback code with a revert of this PR if necessary, but do **not** switch Pages back to branch publishing if relying on the compiled Godot Web artifact. `build/web` is generated by custom workflow; a branch-root Jekyll publish is not an equivalent release.
