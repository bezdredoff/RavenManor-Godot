# Task status ledgers — per-domain write boundary

Read repository-root `AGENTS.md` and `docs/process/AGENT_ORCHESTRATION_RU.md` first. These local rules supplement root policy. Update only the owning `data/raven/production/progress/<domain>.json` plus unique `docs/changes/` evidence; never manually edit generated `dashboard/status.json` or frozen `production_progress.json`. Never auto-merge or claim unverified owner/device/art acceptance.

All **15** domains in `index.json` own independent `<domain>.json`; for `agent/<domain>/<task-id>-topic` edit only that matching shard. `entries` are live status/priority/date/evidence/QA; `assignments` group open P0/P1 with `workstreamId`, open P2 with `p2ReentryGroup`. New planned task may have an assignment before live status; this is not completion evidence. `index.json` is integration-only. Closeout stays in the same domain shard; after actual merge record `merged` with verified PR URL; `accepted` and `device_verified` require human/device proof. Never edit shared workstream/P2 member lists. Test with `python3 scripts/raven/tools/progress_shards.py`, `python3 scripts/raven/tools/build_production_dashboard.py --check` and full CI. Moving IDs between domains is coordinated migration, not a normal agent PR.
